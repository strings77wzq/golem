## Context

项目使用 golangci-lint v2 进行代码质量检查。当前配置禁用了 errcheck 和 gocritic，排除了 `core/database/` 的 gosec 检查。历史遗留代码导致 438 个 linter 警告。

约束（CLAUDE.md）：
- "Lint 零新增 error/warning"
- "测试覆盖率 ≥ 80%"
- "声明完成 = 门禁全绿"

## Goals / Non-Goals

**Goals:**
- G1: 修复所有 revive unused-parameter 警告（~15 处）
- G2: 修复所有 gosec 权限警告（G301/G306）
- G3: 为 G304/G404 添加审核注释
- G4: 5 个低覆盖率包达到 80% 覆盖率
- G5: 启用 errcheck linter

**Non-Goals:**
- 修复所有 gosec G304（文件包含变量）— CLI 工具的预期行为
- 修复所有 gosec G204（子进程）— 需要架构变更
- 达到 100% 覆盖率 — 过度工程

## Decisions

### D1 — unused-parameter 用 `_` 重命名

**决策**：Cobra 命令函数的未使用参数用 `_` 重命名。

**理由**：
1. Go 惯例：未使用参数用 `_`
2. 保留函数签名兼容性
3. 零风险（纯重命名）

**替代方案**：删除参数 — 否决，破坏 Cobra 接口。

### D2 — 权限修复用最小权限原则

**决策**：
- `os.MkdirAll`: `0755` → `0750`（组可读，其他人无权限）
- `os.WriteFile`: `0644` → `0600`（仅所有者可读写）

**理由**：
1. 最小权限原则（安全最佳实践）
2. CLI 工具的配置文件不需要全局可读
3. 符合 gosec 建议

### D3 — G304 用 #nosec 注释

**决策**：对 CLI 工具的文件读取添加 `#nosec G304` 注释。

**理由**：
1. CLI 工具的文件路径来自用户输入是预期行为
2. 路径遍历是用户自己的责任
3. 修复需要添加路径清理逻辑，超出本 Phase 范围

### D4 — 测试补充策略：核心路径优先

**决策**：为每个低覆盖率包补充核心路径测试，而非追求 100% 覆盖。

**理由**：
1. 核心路径测试ROI最高
2. 边界测试可以在后续 Phase 补充
3. 80% 覆盖率是合理目标

## Risks / Trade-offs

- [权限修复] 某些场景可能需要全局可读 → 需要验证具体用例
- [G304 #nosec] 路径遍历风险仍然存在 → 用户自己的责任
- [测试补充] 可能引入脆弱测试 → 只测试核心路径，不测试实现细节
