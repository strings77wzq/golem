## ADDED Requirements

### Requirement: Product identity is explicit
The project SHALL define Golem as a Go-native, local-first AI agent runtime with a path from terminal prototype to deployable gateway.

#### Scenario: New visitor reads the first screen
- **WHEN** a new visitor opens the primary project README or equivalent landing page
- **THEN** the first screen presents Golem's Go-native, local-first agent runtime identity and deployment path without requiring the visitor to infer it from a feature list

### Requirement: Target users are prioritized
The project SHALL identify Go backend, CLI, and infrastructure developers as the primary audience and developers learning agent runtimes as a secondary audience.

#### Scenario: User evaluates fit
- **WHEN** a developer reads the positioning section
- **THEN** they can determine whether they are in the primary or secondary target audience

### Requirement: Non-goals are documented
The project SHALL document that Golem is not a hosted SaaS, no-code agent builder, Python agent framework clone, or chatbot-only demo.

#### Scenario: User compares project categories
- **WHEN** a user compares Golem with hosted SaaS, no-code, Python-first, or chatbot-only projects
- **THEN** the documentation makes Golem's intended category boundaries clear

### Requirement: Messaging uses practical engineering tone
The project SHALL use practical, engineering-first, maturity-transparent language in product-facing surfaces.

#### Scenario: Capability maturity is described
- **WHEN** a product-facing document describes a capability that is incomplete or still being hardened
- **THEN** it labels the capability as a path, planned work, beta, or in-progress rather than presenting it as fully complete
